# Contributing

Start protocol changes in the specification. Explain the required behavior, failure cases, and compatibility effect. Keep application-specific behavior outside the core contract.

For a wire change, update the message reference, examples, planned schemas, and shared conformance cases together. Client APIs may use native language conventions but must preserve the same protocol behavior.

Do not commit local reference clones, credentials, build output, or dependency caches. Preserve attribution and license notices when importing third-party material. The DASP project license remains an open project decision.
