# Documentation

Start with the [core specification](specification/README.md). Read the [message reference](specification/messages.md), [recovery rules](specification/recovery.md), and [example](specification/example.md) next.

The core specification, message reference, recovery rules, and [security and version rules](specification/security-and-versioning.md) define the draft contract. Examples explain that contract. Design notes and client plans are informative.

`MUST` states a requirement. `MUST NOT` states a prohibition. `SHOULD` states a recommendation. `MAY` states an option. These words apply to this draft only; they do not claim an implemented or released standard.

The specification is the source of truth. Planned JSON Schema files will describe message structure. Shared conformance cases will describe behavior. Neither client language will define the protocol for other languages.

Before the first implementation release, resolve the blocking questions in the [design notes](design/decisions.md) and complete the [conformance plan](../conformance/README.md).
