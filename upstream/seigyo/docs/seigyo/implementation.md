# Seigyo Protocol: Implementation

This file is nonnormative. It records current code, suggested work order, and
open decisions. Only the versioned rules and wire shapes accepted for a
published protocol profile can bind an independent client.

## Decisions to record

| Question | Options | Recommendation and status |
| --- | --- | --- |
| Generic Update | Keep open nested payload; use one carrier with closed event variants; use one Signal type per event. | Resolved for coding v1: one carrier with ten closed advertised variants. A new variant needs a new version or selected capability. |
| Read requests | Use a request Signal or an RPC frame. | Resolved for coding v1: ADR 0019 Phoenix RPC frames carry typed read arguments and return result Signals. A future transport must keep the same meaning. |
| Coding activity | Keep only admission/outcome plus Trace; save bounded semantic tool/effect and approval activity. | Save the semantic activity in a coding extension. Keep token deltas temporary. Add a coding activity ADR before event schemas. |
| General agent | Make the current Workspace and Jido AI fields universal; add a versioned common profile and coding extension. | Add a new common profile ADR. It must amend the scope of ADRs 0010 and 0015 and the foundation plan. Exact v2 shape remains open. |
| Remote reasoning | Send current Progress and Trace thinking fields; omit or redact them by explicit profile policy. | The current remote coding profile clears Progress and Trace thinking. Client schemas reject reasoning text. Record a richer visibility and redaction policy before any remote reasoning access. |
| Caller policy | One trusted local caller; authenticated owner and explicit shares. | Keep one trusted caller for local proof. Choose and test remote owner/share rules before exposure. This is still open. |
| Event retention | Keep all events; add a stated retention floor and gap response. | Keep all events in the first proof. Add a floor only with Store conformance and View loss rules. |
| Collaboration identity | Treat each connection as a User; use stable Users, durable Session Members, and temporary Clients. | Use stable Users and Members. Keep presence temporary. Add a multiplayer identity ADR before remote sharing. |
| Shared text | Put every keystroke in Session Updates; use separate per-document OT revisions. | Use per-document OT revisions and snapshots. Add an OT ADR before an editable shared document. |
| Work and schedules | Treat every action as a client Command; add Work identity for client, Agent, and Schedule origins. | Add Work identity and parent links in a new protocol version. Decide schedule trigger, overlap, and recovery policy in the same or a following ADR. |
| Session list order | Expose current local Session ID paging; choose another declared order. | Define a bounded, authorized page with an opaque cursor. Document concurrent-change behavior before release. No v1 list type is assigned. |
| Command to Work mapping | Require one Work per Command; let closed command kinds create zero, one, or several Work units. | Save the intent at admission and each link before report or dispatch. A duplicate reuses saved links. Decide exact Receipt and Update shapes by ADR. |
| Old stored events | Render any current EventRecord as v1; translate or migrate to a closed remote event variant. | Translate or migrate all retained events before remote replay. Define a failure and View recovery rule for any record that cannot be represented. Never skip a sequence. |
| Remote errors and discovery | Infer support from a version segment; publish an operation and capability manifest with exact error mappings. | Resolved for local coding v1: the generated bundle publishes capabilities, operation mappings, stable errors, limits, schemas, exact frames, and conformance-case links. The raw verifier checks the live join, every advertised operation and control, unadvertised operation and event rejection, and failure envelopes without typed protocol modules. HTTP is future work. |
| Profile selection | Bind capabilities to a live socket only; carry the choice on each call or use a stable negotiation token. | Resolved for coding v1: the WebSocket join selects the profile, each Session saves protocol version `1` and profile `coding`, and open returns both values. A future transport must define equivalent selection. |
| Remote Update pages | Nest complete Update Signal envelopes; carry the same closed Update data used by live Signals. | Resolved for coding v1: `UpdatesPage` carries the same closed `Update.data` values used by live Update Signals. |
| Remote outcomes | Expose the internal Agent request ID; return a safe outcome payload and use Command ID for client correlation. | Resolved for coding v1: terminal variants carry Result ID and use Command ID for client correlation. Internal Agent request identity stays private. |
| Session open race | Compatible concurrent opens in one runtime return one saved Session; a different explicit Workspace conflicts. | Add crash recovery between Agent start and Store create. Do not claim open is idempotent across nodes before shared admission proof. |
| Work origin keys | Reuse Command IDs for all Work; use a distinct stable child key and Schedule occurrence ID. | Use distinct origin keys and save each Work link before dispatch. Fix their scope, ID format, and conflict result in the Work ADR. |
| Work state and children | Infer parent outcome from a child state; save a parent completion policy and explicit state transition graph. | Fix allowed transitions, waiting reasons, child policy, cancellation evidence, and uncertain reconciliation before Work status is public. |
| Schedule time | Require one set of timing fields for all triggers; give each trigger type only the fields it needs. | A one-shot UTC trigger is a small first slice. Decide missed fire, edit, disable, and overlap outcomes for each published trigger type. |
| Sandbox scope | Treat Sandbox as a Workspace or an anonymous process; give it separate identity, owner, binding, and cleanup rules. | Keep Workspace and Sandbox IDs separate. Fix access, reuse, and retention before clients can select an existing Sandbox. |
| Multi-node authority | Treat a shared Session Store as sufficient; fence Session admission, Workspace effects, and Agent state writes as separate authorities. | Prove concurrent admission, stale-owner rejection, Agent revision joins, and provider fence limits before a multi-node claim. |

Accepted ADRs remain decision records. They must not become parallel Signal
catalogs. An ADR update must name its change to the accepted coding slice;
this document does not silently revise those decisions.
